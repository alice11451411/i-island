# I岛 MVP 技术设计

日期：2026-10-31

用户 PRD 是功能与产品设计依据。推荐交付原生微信小程序 + Node.js 共用后端 + 浏览器本地演示。已按用户 PRD 与默认自主推进要求实现本地可运行演示，实际验收及未接入项见 README。

## 推荐方案

Node.js 24 内置 HTTP 与 SQLite，避免首版依赖构建服务；原生小程序直接导入微信开发者工具。浏览器界面复用同一 API，支持检查交互和演示完整流程。纯界面方案不验证服务端状态，云端方案需要用户的 AppID、域名及模型配置。

## 数据与状态

用户资料、授权字段、Agent 档案、授权版本、匹配、双方意向、文字消息、拉黑、举报与事件记录持久化到 SQLite。用户先确认已成年与资料用途；原始简介、精确位置与联系方式不参与交换。

匹配只在双方开启且资料授权有效时创建；兴趣、目的和边界参与排序。交流最多 6 条轮流消息，规则模式只引用已授权字段。报告注明 AI 推测。任一方拒绝、解除、拉黑或删除账号后，服务端拒绝继续聊天。真人聊天必须双方同意。

## 本地演示与真实接入

本地演示使用明确标记的虚构样例、规则生成和本地会话，不宣称真实微信登录或真实模型输出。可选兼容 Chat Completions 的模型配置只通过服务端环境变量读取。真实模式使用微信 code 换取服务端身份，禁止客户端自报 userId；无密钥时真实模式不能自动降级为演示。

浏览器允许在两个虚构身份之间切换以验证双方同意。演示身份切换只在 DEMO_MODE 开启时提供。不会自动伪造对方同意或收到的真人消息。

## 界面

五个主要页面：小岛首页、Agent 创建编辑、Agent 交流、缘分报告、消息/我的。浏览器提供响应式预览；小程序采用相同的柔和浅绿、米白、暖橙与圆角卡片。

## 验收

先为授权字段投影、轮数限制、双方同意、拉黑隔离、资料撤回和账号删除写失败测试。实现后跑 Node 测试、语法检查与浏览器流程，检查桌面和移动宽度。微信真机与正式内容审核接入在缺少平台配置时明确列为未验收项。
